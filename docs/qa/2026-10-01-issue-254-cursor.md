# Issue #254 cursor verification

The next issue after #251 in [the audit queue](https://github.com/vivekpatel99/my-portfolio-webisite/issues/267) is [#254](https://github.com/vivekpatel99/my-portfolio-webisite/issues/254). It was open with no overlapping PR. The baseline was current `develop` at `282d2a20e4eec5bf947303d88efe7df91d3dc860`.

## Reproduction and change

Before movement, Chromium and WebKit computed `cursor: none` on the body while the dot was at −108, −108. The lightbox image, backdrop, and zoomed viewport also had `cursor: none`; the dot's z-index was 9999 below the overlay's 10000. The original state-based hook caused 241 React commits during 241 mouse moves.

`CustomCursor` now stores pointer coordinates in MotionValues and keeps the first-position flag in a ref. The first move jumps both springs to the pointer before enabling cursor hiding. Media changes and unmount release the class and listeners. The cursor is above the modal at z-index 10001. The unused state-based mouse hook and its test were removed.

The dot remains 16×16, purple `#9372FF`, with difference blending and spring stiffness 500 and damping 28. [The side-by-side recording](assets/issue-254-cursor-before-after.webm) shows the same pointer path outside the lightbox, before on the left and after on the right. Sampled frames show comparable tracking and the same appearance. Physical mouse feel still needs owner acceptance.

Keyboard focus remained inside the dialog with a 3px outline. Zoom reached 150%, and Escape restored the gallery opener. Coarse pointer, reduced motion, JavaScript disabled, and blocked entry scripts retained native cursors.

## Performance measurement

Run `QA_PREVIEW_URL=http://127.0.0.1:3100 node tools/measure-cursor-performance.mjs /tmp/cursor-metrics.json` against the production preview. It uses Chromium at 1350×940, 4× CPU throttling, necessary-only seeded consent, the home page scrolled to 1200px, and 241 paced mouse moves over two seconds. There are three fresh-context runs per motion mode. The commit counter must observe the initial React render before it can report movement counts. Exit status is nonzero when the normal-motion zero-commit or 200ms task-time gate fails.

The measured baseline had 241 commits each, task time 318.821–406.186ms, and script time 98.593–116.569ms. The first fix had zero commits, task time 241.735–265.288ms, and script time 42.402–44.192ms. The final delivered-source run again had zero commits, with task times of 355.313, 232.922, and 241.709ms. Median task time fell from 377.892ms to 241.709ms, but every final run exceeded the 200ms acceptance gate. Final script times were 66.770, 37.845, and 34.366ms; layout remained zero. Reduced-motion controls had zero commits and task times of 86.639, 51.461, and 46.690ms. These are local lab measurements with visible run-to-run variation, not field metrics.

[Raw matched measurements](assets/issue-254-cursor-metrics.json) include the baseline, final source, and two rejected experiments. `will-change: transform`, containment, isolation, and body placement did not meet the gate consistently. They were not shipped. A diagnostic trace attributed the remaining work to spring-driven paint/compositor lifecycles, rather than React or layout. No frame-rate cap or blending change was added to meet the number.

Fresh `/code-review` Standards and Spec reviews ran separately against the frozen precommit code tree. Standards found no actionable code-quality findings. Spec found no additional application defect and confirmed the outstanding task-time and cursor-feel acceptance gates. Codex incorporated the final measured values into this report and independently checked the final documentation. The reviewed application, tests, and measurement tool were unchanged after review.

The Fix Root Causes principle kept the change in cursor activation and coordinates. Prove It Works required rendered and matched measurement evidence. Attack the Premise prompted a body-placement experiment after compositor hints failed; that experiment also failed the gate.

## Babysit follow-up

The PR's first CI run failed only in `qa-visual.spec.js`: it moved the pointer before the asynchronously mounted cursor listener existed. The smoke test now waits for `[data-custom-cursor]` before moving. The same test passed locally, and the full cursor matrix passed 20 tests with 12 expected skips in Chromium and WebKit.

Three additional local-only movement experiments were measured under the same 1350×940 Chromium, 4× CPU, 241-move, two-second conditions. Frame-coalescing had normal-motion task times 399.447, 379.660, and 358.867ms (median 379.660ms); a CSS transition prototype had 236.810, 371.514, and 389.879ms (median 371.514ms); and a 60Hz input cap had 308.474, 316.651, and 545.494ms (median 316.651ms). All retained zero React commits, but none met the 200ms task-time limit, so all were discarded. Their raw results are recorded in the metrics JSON.
