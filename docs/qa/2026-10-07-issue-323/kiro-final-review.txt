## New position oracle (source review)

The init script wraps `HTMLElement.prototype.scrollIntoView`. At call time it records `rect.top + scrollY - parseFloat(scrollPaddingTop)`, clamped to `[0, scrollHeight - innerHeight]`. `expectAnchorArrival` then takes the last `scrollIntoView` record for the target and requires the final `scrollY` to be within 2px of it, plus `toBeFocused` and `toBeInViewport`.

- **Fails closed:** if `scrollIntoView` is never called, the distance is `Infinity`. If the padding can't be parsed, it is `NaN`. Neither passes `< 2`.
- **Handles the retry:** `findLast` uses the last of the possibly repeated calls.
- **Recorded before the entrance animation:** the geometry is taken before the SectionAnimator's 12px move. A later visual shift doesn't change the scroll position, which is what's being compared.
- **Accepted limitation:** the oracle checks the scroll position the call produced, not where the target ends up after later layout shifts, such as images loading above it. `toBeInViewport` only partly covers this. It isn't a defect for this issue's "behaviour unchanged" scope.
- **Malformed cases:** zero recorded `scrollIntoView`/`focus` calls on the tracked ids, no change in `scrollY`, focus stays where it was (or on `BODY` for cold load), no page errors after 2200ms, then recovery through a footer link.
