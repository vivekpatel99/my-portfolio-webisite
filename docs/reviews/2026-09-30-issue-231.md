# Issue #231 contact failure verification

The contact form now shows a fixed retry/email instruction for unknown submission failures. Only the existing validation message and the two backend rate-limit messages may appear verbatim.

Related issue: [#231](https://github.com/vivekpatel99/my-portfolio-webisite/issues/231).

## Baseline and reproduction

- Current `develop` and starting HEAD were `8fe91fb930275289bfe1f8f1f1ec3d0083e226f4`.
- The current checkout was clean on `t3code/implement-issue-231`. No worktree was created.
- Codex built the unchanged production frontend with the synthetic contact deployment URL and disabled analytics/Sentry configuration.
- In T3, an in-memory WebSocket returned `[Request ID: synthetic-audit] Server Error` and a synthetic stack line. The visible failure toast displayed the request ID, stack text and `Called by client`.
- All contact submissions in this verification used synthetic input and an isolated transport. No real lead or email was submitted.

## Change and acceptance evidence

`Contact.jsx` uses an exact-message allowlist. Unknown `error.data`, `error.data.message` and `error.message` cannot supply toast text. The fallback is:

> We couldn't send your request. Please try again, or use the email address on this page.

| Acceptance criterion | Observed result |
| --- | --- |
| Unknown failure text excludes request IDs, CONVEX, Server Error and stack text | Component regressions cover ten unknown rejection shapes. The browser suite checks visible feedback and announcements for diagnostic fragments. T3 independently reproduced the fixed result for ordinary and structured errors. |
| Offer recovery and preserve entered values | The toast gives retry/email guidance. The existing `mailto:contact@vivekapatel.com` remains available. Browser checks preserve name, email, description and budget through failure, then clear them after successful retry. |
| Keep expected errors actionable | Browser transport checks decode actual ConvexError data for validation, global rate limit and per-email rate limit, then assert their exact safe messages. |
| Preserve duplicate-submit guards | The pending browser scenario attempts another submit and observes one mutation. A keyboard Enter retry produces the second mutation and success feedback. |
| Preserve telemetry handling | Capture remains suppressed for the validation sentinel and retains the sensitive form source for other failures. Component tests verify both paths and the original rejection passed to capture. No telemetry code changed. |
